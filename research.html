Reasonable Programming Languages

Premise 1: Rust is hard to learn and use due to its complex type system. We need high-level counterpart for non-systems software: "What is to Rust as Python is to C?".

Premise 2: Formal verification of code is hard due to aliasing. Formal verification by "programming in mathematics" a la CompCert works well, but programming with pure mathematical functions is difficult for programmers and leads to slow code.

Goal: Develop languages that are easy to use, performant, and a basis for formal verification, without a complex type system.

  • Create practical, "Pythonic" programming language that simultaneously serves as a foundation for formal proof.
  • Copy-on-alias semantics to solve mathematical inconsistency with imperative constructs.
  • Enable efficient data representations, compiler optimizations.
  • Safe and seamless Rust interoperability (conventional high level languages don't uphold critical Rust "aliasing xor mutability" invariant).
  • Borrow checker becomes a compiler optimization and linter.

Helpful skills: Strong mathematical background, interest in type theory or logic, language design taste, compiler development, proof automation with classical methods and AI.

Related: Lean, F*, Coq, Rust, Swift, Hylo, Aeneas, Creusot, ...

Live Languages and Program Logics

Premise: Current languages and program logics guarantee memory safety and partial correctness, but typically not properties like liveness and total correctness.

Goal: Develop type systems and program logics that establish strong correctness properties for concurrent programs.

  • Develop advanced type systems and logics for termination, liveness, and concurrency.
  • Support practical concurrency constructs (message passing, locks, condition variables, CAS).
  • Compositional type checking and verification.

Helpful skills: Strong mathematical background, interest in linear types and separation logic, concurrent programming.

Related: Separation logic, Iris, session types, λlock, LTL, dynamic logic, LiLi, TaDa, ...

Network Verification

Premise: Networking is an attractive domain for formal methods because infrastructure is critical, and problems are often decidable because behavior is constrained by latency and throughput requirements.

Goal: Develop network modeling and query languages powered by modular, scalable solver suites for practical decision problems in networking.

  • Expressive Modeling: Handle unbounded packet and switch states.
  • Expressive Queries: Support transducers, trace properties, quantitative analyses (failures, latency, throughput, queuing).
  • Synthesis: Automated generation of verified network configurations.

Helpful skills: Strong mathematical background, interest in the development of theoretical decision procedures, algorithmic and engineering of practically fast solvers, knowledge of networking domain.

Related: NetKAT, KATch, HSA, Veriflow, Minesweeper, Batfish, APV, Delta-net, Plankton, ...
