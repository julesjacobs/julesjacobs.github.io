Vox

Refinement types, ghost code and ownership for OxCaml

Watch the talk Code on GitHub

Why

As more code is written by AI agents, it gets harder for people to keep track of what a code base does. Specifications help: you read what a function promises instead of how it is implemented, and the compiler checks that the implementation keeps the promise. Vox brings this to OxCaml without leaving the language. Specifications are types, proofs are written as code, and proofs are erased before code generation, so they cost nothing at run time.

An example

The type of hi says that the caller must pass ordered bounds, and the result type says that the result lies between them. Vox proves both from the code, and the client calls clamp as usual:

let (clamp @ total) (lo : int) (hi : {h : int | lo <= h}) (x : int) :
    {r : int | lo <= r && r <= hi} =
  if x < lo then lo else if x > hi then hi else x

let bounded (x : int) : {r : int | 0 <= r && r <= 10} =
  clamp 0 10 x

A function that does not keep its promise is rejected at compile time, with a counterexample:

1 | let wrong (x : int) : {r : int | 0 <= r && r <= 10} = x
                                                          ^
Error: Refinement could not be proved (counterexample: x = -1)
1 | let wrong (x : int) : {r : int | 0 <= r && r <= 10} = x
                                     ^^^^^^
  The refinement is stated here.

Both examples are from bounded_clamp.ml, which also shows that clamp 10 0 x is rejected because the bounds are in the wrong order.

How it works

  • Refinement types. A type can carry a predicate, such as {r : int | lo <= r}. The compiler turns each function's refinements into verification conditions and asks an SMT solver to prove them.
  • Ghost code. Proofs that the solver cannot find on its own are written as ghost arguments, ghost blocks and lemmas. The compiler checks them and then erases them.
  • Ownership. Ghost tokens stand for ownership of mutable state. OxCaml's uniqueness modes make them affine, which is how Vox specifies mutable cells, hash tables and communication between domains.

Verified programs

The repository has 25 larger verified programs. Each name links to the file where its specification is stated.

Data structures

  • Flat hash table: a mutable hash table that behaves as a finite map
  • AVL sets: exact membership after add and union; equal holds exactly for equal sets
  • Functional queue: a two-list queue that acts on the list of its elements
  • Sorted arrays: search, insertion and removal proved against the elements
  • Sparse array overlays: the value at every index after any sequence of writes and clears
  • Mutable lists and trees: in-place list reversal and tree mirroring against a model of the heap
  • Doubly linked rings: insertion, removal, reversal and moving ranges between rings
  • Online union–find: implements a partition model within inverse-Ackermann amortized cost
  • E-graphs: equalities come with a derivation from the caller's rewrite rules

Algorithms

  • Merge sort: a sorted permutation using at most n⌈log₂ n⌉ comparisons
  • Quicksort: in place, sequential and parallel; the result is a sorted permutation
  • Myers diff: an edit script with the minimum number of insertions and deletions
  • CDCL SAT solver: terminates; Sat comes with a model, and Unsat means none exists
  • DFA equivalence and minimization: counterexample words, and minimal DFAs with the same language
  • Regular expressions: a matcher and a conversion to DFAs that preserve the language
  • Quantifier elimination: for formulas over a three-element chain, preserving their meaning

Compilers and languages

  • Hindley–Milner type inference: sound and principal with respect to a declarative typing relation
  • Compiler to WebAssembly: valid bytes, safe execution and agreement with the source
  • Register allocation: preserves every finite run of the programs it allocates
  • Constant folding: preserves evaluation, including wrapping addition

Systems and concurrency

  • LZ4 block compression: compressor and decoder equal to a specification, with a round trip
  • Incremental HTTP parser: sound and complete for a request grammar, independent of chunking
  • Textbook RSA: modular exponentiation on unbounded integers and the RSA round trip
  • One-shot channels: the receiver takes the payload only after the sender has put it there
  • Locks: acquire and release hand out and take back exactly the guarded cell

Try it

  1. Check out the vox branch and configure it with a local install prefix, as described in the README.
  2. Install Z3 and put it on your PATH.
  3. Run ./dev init, then ./dev test vox/bounded_clamp.ml. Your own files need the flag -extension refinement_types.

The tour of the tests walks through the examples, and Verification programming explains how to write contracts and reusable proofs. When a goal is rejected, compile with -dvc to see the goal, its assumptions and the solver's model.

Status

Vox is research software under active development. It builds on OxCaml's modes; our paper Mode Crossing (ICFP'26) is about how values of suitable types move between modes. If you would like to use Vox or work on it, email me.
