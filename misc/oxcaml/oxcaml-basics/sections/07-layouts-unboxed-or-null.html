Layouts, Unboxed Values, And or_null

Unboxed Records

Teaching question. What visible syntax tells you this record is not an ordinary boxed record?

New idea. Unboxed records have explicit syntax and a non-value representation.

type point = #{ x : float#; y : float# } let origin = #{ x = #0.0; y = #0.0 } let get_x p = p.#x

Normal Tuples Require value Elements

type bad = int * #(string * bool)

Unboxed Tuple Destructuring

let swap #(x, y) = #(y, x)

Labeled Unboxed Tuples

let flip #(x, y, ~lbl:z) = #(~lbl:z, y, x)

Unboxed Number Literals

let f64 = #3.14 let i32 = #123l let i64 = #456L let native = #789n let id_float (x : float#) = x

float# option Is Not A Normal Option

Teaching question. Why does float# option fail even though ordinary float option is fine?

New idea. Ordinary polymorphic containers still expect value-like arguments.

type bad = float# option

Unboxed Array Type Syntax

type float_array = float# array type int32_array = int32# array

or_null Construction And Pattern Matching

Teaching question. How does or_null give an optional result without ordinary option allocation?

New idea. Null and This give a non-allocating optional shape.

let hd_or_null = function | [] -> Null | x :: _ -> This x let value_or default = function | Null -> default | This x -> x let first = value_or "empty" (hd_or_null ["first"; "second"]) let missing = value_or "empty" (hd_or_null [])

or_null In A Result Type

module type Lookup = sig type key type value val find : key -> value or_null end

Unboxed Product Return

let quote_stats bid ask = let spread = ask -. bid in #(~midpoint:(bid +. (spread /. 2.0)), ~spread)
