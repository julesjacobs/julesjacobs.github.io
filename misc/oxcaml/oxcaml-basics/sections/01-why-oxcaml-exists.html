Why OxCaml exists

OxCaml starts from OCaml's safe, high-level programming model and adds explicit, compiler-checked control over low-level behavior needed for high-performance code: parallelism, allocation, and memory layout.

OxCaml is still under active development. New features and changes are driven by concrete developer demand, especially from performance-sensitive applications.

Parallelism

Parallel programs must not introduce data races. OxCaml's type checker tracks which functions can run in parallel and how they may access captured mutable state.

Allocation

A GC pause at the wrong time is unacceptable in low-latency code. OxCaml adds stack allocation, with type checking to ensure stack-allocated values do not outlive the stack frame that allocated them.

Memory layout

High-performance programs need cache locality, fewer pointer indirections, and fewer heap allocations. OxCaml uses types and layouts to give control over memory layout.

OxCaml language features

To allow this extra control safely, OxCaml adds several type system features.

  • Modesx @ local, x @ shared, (unit -> unit) @ portable, f @@ portable — checked requirements on how a value may be used, such as whether it may outlive its region or whether a parallel function may read captured mutable state.
  • Stack allocationstack_ expr, exclave_ expr — allocate temporary values without putting them on the heap.
  • Layouts and unboxed valuesfloat#, #(x, y), #{ x : float# } — control memory layout.
  • Kindstype t : value mod portable, ('a : value & immediate) — record what modes or layouts every value of a type can support.
  • Templateslet%template, [@mode], [@kind] — generate related definitions across modes, kinds, and layouts.

Learning goals

By the end of the course, you should be able to:

  • read small OxCaml examples that use parallelism, stack allocation, and representation layouts;
  • recognize common annotations such as @ local, @ contended, @ portable, and layout annotations in real signatures;
  • explain common compiler errors involving escaping values, unsafe mutable access, heap allocation, or representation mismatch;
  • choose the relevant OxCaml feature for small performance-sensitive examples.
