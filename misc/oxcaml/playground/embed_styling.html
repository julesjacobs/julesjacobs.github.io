Styling OxCaml Embeds

The embeddable playground is designed to be styled from the host page. Use stable CSS custom properties for normal theming, classes for reusable variants, and the JavaScript API for light, dark, and auto theme mode.

Quick Start

Put an <oxcaml> tag on the page, give it classes or inline custom properties, and load oxcaml-embed.js. The embed script replaces the tag with a light-DOM widget and preserves presentation attributes from the original tag. 

<style>
  .lesson-example {
    --oxcaml-accent: #2563eb;
    --oxcaml-editor-min-height: 7rem;
    --syntax-keyword: #6d28d9;
  }
</style>

<oxcaml class="lesson-example" data-oxcaml-theme="auto">
let square x = x * x

let () =
  Printf.printf "square = %d\n" (square 7)
</oxcaml>

<script src="./oxcaml-embed.js"></script>
let square x = x * x let () = Printf.printf "square = %d\n" (square 7)

Execution Modes

A widget normally runs the source as a program. Add check when an example should only type-check, or utop when the source should behave like toplevel phrases. In utop mode, terminate phrases with ;; and the transcript shows evaluated values and inferred types for each phrase.

ModeMarkupUse it for
Run<oxcaml>Small programs that print output or emit rendered HTML.
Check<oxcaml check>Type-checking examples, expected errors, and snippets without side effects.
Utop<oxcaml utop>Interactive lesson examples where each phrase should show its value and type.
 
<oxcaml utop data-filename="lesson_values.ml">
let language = "OxCaml";;
let answer = 40 + 2;;
Printf.sprintf "%s: %d" language answer;;
</oxcaml>
let language = "OxCaml";; let answer = 40 + 2;; Printf.sprintf "%s: %d" language answer;;

Programmatic mounts use the same mode names: 

window.OxCamlPlayground.mount(element, {
  mode: "utop",
  source: "let x = 1 + 2;;",
});

Output Panel

By default, completed widgets keep the output panel visible and show (no output) when the program or check produced no transcript. Add data-oxcaml-empty-output="hide" to remove the output panel only when there is no transcript and no inferred-type panel.

Diagnostics, warnings, exceptions, stdout, rendered HTML output, and inferred types still show the output panel. The panel also remains visible while the widget is loading or running. 

<oxcaml check data-oxcaml-empty-output="hide">
let add_tax cents =
  cents + (cents / 10)
</oxcaml>

Programmatic mounts use the same setting name: 

window.OxCamlPlayground.mount(element, {
  mode: "check",
  emptyOutput: "hide",
  source: "let add_tax cents = cents + (cents / 10)",
});

Theme Mode

Every widget has a theme mode: auto, light, or dark. Auto follows prefers-color-scheme. Light and dark force the widget to that mode.

Canonical Settings

The embed API intentionally keeps one public spelling for each setting. Older-looking aliases such as theme, data-theme, and filename are not part of the supported styling API.

SettingCanonical form
Execution mode in markup<oxcaml>, <oxcaml check>, or <oxcaml utop>
Empty output paneldata-oxcaml-empty-output="show|hide"
Theme mode in markupdata-oxcaml-theme="auto|light|dark"
Theme mode in JavaScriptwindow.OxCamlPlayground.setThemeMode(mode, target?)
Filename for diagnosticsdata-filename="example.ml"
Reusable visual variantclass="..."
One-off visual overridesstyle="--oxcaml-accent: ..."

Markup

Use data-oxcaml-theme on the original <oxcaml> tag. The generated widget root keeps the same attribute. 

<oxcaml data-oxcaml-theme="dark">...</oxcaml>
let mode = "forced light" let () = print_endline mode let mode = "forced dark" let () = print_endline mode

JavaScript

The wrapper exposes window.OxCamlPlayground.load, a promise for the module, and then installs the public API on window.OxCamlPlayground. 

await window.OxCamlPlayground.load;

// Update every mounted widget and make future widgets use the same mode.
window.OxCamlPlayground.setThemeMode("dark");
window.OxCamlPlayground.setThemeMode("light");
window.OxCamlPlayground.setThemeMode("auto");

// Read the global mode.
const mode = window.OxCamlPlayground.getThemeMode();

Pass a mounted editor object, a generated .oxcaml-embed root, or a container element to update a smaller scope. Use setThemeMode for all programmatic theme changes. 

const editor = window.OxCamlPlayground.mount(element, {
  source: "print_endline \"hello\"",
});

window.OxCamlPlayground.setThemeMode("light", editor);
window.OxCamlPlayground.setThemeMode("dark", document.querySelector("#chapter-2"));

The buttons above call setThemeMode on this page, so they are also a working example of the global theme API.

Preserved Attributes

The generated widget root keeps useful presentation attributes from the original <oxcaml> tag:

  • id for anchors and direct selection.
  • class for reusable styling variants.
  • style for per-widget custom properties.
  • title, aria-*, and data-*.
<oxcaml
  id="intro-example"
  class="compact-example flat-example"
  data-topic="functions"
  aria-label="Runnable square function"
  style="--oxcaml-editor-min-height: 5.5rem">
let square x = x * x
</oxcaml>
let square x = x * x let () = Printf.printf "%d\n" (square 9)

CSS Custom Properties

Set variables on an ancestor to theme a whole article, on a class to create a named variant, or inline on one <oxcaml> tag. Variables inherit into widgets, and widget-local variables override page-level values. 

.tutorial-page {
  --oxcaml-accent: #0f766e;
  --oxcaml-editor-min-height: 8rem;
}

.tutorial-page .warning-example {
  --oxcaml-accent: #b45309;
  --syntax-string: #166534;
}

Variables should cover most styling. These class names are stable hooks for layout or advanced rules.

SelectorElement

  border-radius: 0;
